User journey

  1. Create a first project on Setup guide, step 1: Types a project name and selects Create project. Success: The project appears in the workspace and the guide moves to step 2. If it fails: error state.
  2. Leave the guide for later on Setup guide, step 1: Selects Skip the guide. Success: The guide closes and the empty workspace stays usable. If it fails: error state.
  3. Pick the guide up again on Help menu: Opens Help and selects Reopen the setup guide. Success: The guide opens at the step the user left. If it fails: empty state.

Accessibility requirements

  • contrast (static): Text and status colours meet 4.5:1 on background and surface; borders and the focus ring meet 3:1.
  • focus-visible (static): Every control shows a 3px focus ring in the focus colour; no outline is removed without a replacement.
  • keyboard (browser): The guide can be completed, skipped and reopened with the keyboard alone, in visual order.
  • target-size (browser): Buttons and inputs are at least 44 by 44 CSS pixels.
  • reduced-motion (static): With reduced motion requested, transitions are removed and the final state shows at once.
  • landmarks (static): Header, nav, main and footer landmarks; a skip link is the first focusable element.
  • form-errors (static): The project-name error is tied to the field with aria-invalid and aria-describedby and says how to fix it.
  • text-resize (browser): At 200 percent text size and 320 CSS pixels wide nothing is clipped and no horizontal scroll appears.
  • status-messages (assistive-tech): Loading and success messages are announced politely; errors are announced assertively.
